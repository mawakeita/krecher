## Evening: hotspot for class (done)
- The Pi has no screen, so it can only join Wi-Fi it already knows. School Wi-Fi needs a NetID login (`newschool`, `eduroam`) or a browser sign-in page (`newschool-guest`), so class uses a dedicated hotspot device.
- Saved on the Pi as NetworkManager connection `hotspot` with `connection.autoconnect-priority 10` (preferred over home Wi-Fi when it's on):
  `sudo nmcli connection add type wifi con-name hotspot ifname wlan0 ssid "<SSID>" wifi-sec.key-mgmt wpa-psk wifi-sec.psk "<password>" connection.autoconnect-priority 10`
- `sudo nmcli connection up hotspot` switched the Pi over. The SSH session froze, as expected: its tunnel went down with the old network.
- **Problem found:** `ssh krecher` then hung. The node still held port 2222 for the dead tunnel, so the Pi's new tunnel couldn't take it. Fixed by killing that `sshd` process on the node; the Pi's autossh reclaimed the port.
- **Prevention:** node sshd keepalive (`system/node-sshd-keepalive.conf`): dead tunnels now drop within ~90 s.
- Quick fix if it happens again: `ssh mynode`, `sudo ss -tlnp | grep 2222`, `sudo kill <pid>`, wait 30 s, `ssh krecher`.
